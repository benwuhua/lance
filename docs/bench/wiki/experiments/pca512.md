# PCA-512 Experiment

## Goal

Test whether TruncatedSVD dimensionality reduction (1024→512) improves vector search latency, especially on OBS where network transfer is the bottleneck.

## Setup

- **Method**: TruncatedSVD(512) trained on 500K vectors from shard-0
- **Variance retained**: 96.63%
- **Dataset**: Same 1B FineWeb-Edu, 5 shards x 194M rows, reduced to 512-dim
- **Index**: IVF_RQ, 13,107 partitions/shard (same as baseline)
- **GT**: Flat search on original 1024-dim shard-0, converted to positional indices
- **Scripts**: `benchmarks/cohere/setup_pca.py` (build), `benchmarks/cohere/test_pca512_v2.sh` (sweep)

## Findings

1. **Recall ceiling ~0.97**: 96.6% variance retained = hard limit. Cannot reach 0.99+ regardless of nprobe/rf settings. The missing 3.4% of variance permanently loses some neighbor relationships.

2. **DRAM: ~10% faster at low nprobe**: Lower-dim distance computation is faster. At high nprobe, the savings diminish because CPU cost dominates over distance computation savings.

3. **OBS: 3-7% faster consistently**: Network transfer halved (512x4B vs 1024x4B per vector). The improvement is consistent across all configs because network is always the bottleneck.

4. **rf unit cost**: PCA OBS ~9.3s/rf, Baseline OBS ~10s/rf. Similar, because CPU dominates within each rf unit.

5. **Recommendation**: PCA-512 best for OBS deployment when recall <= 0.95 is acceptable. Not recommended for DRAM when recall > 0.97 is needed.

## Lessons Learned

1. **GT sampling alignment**: `rng.choice(n, 5)` != `rng.choice(n, 8)` in numpy — different random indices with same seed. Must match benchmark exactly.

2. **Cross-dataset recall**: Convert _rowid to positional indices for comparing results across datasets with different internal structures but same row order.

3. **obsutil sync vs cp**: Use `sync` for non-interactive uploads. `cp` requires per-file confirmation.

4. **Parallel shard rebuild**: Use `--only-shard N` for parallel processing. 4 processes x 200GB = 800GB RAM usage, well within 493GB available (each process ~50GB peak).
